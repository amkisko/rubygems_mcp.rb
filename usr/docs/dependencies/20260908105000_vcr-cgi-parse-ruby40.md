# vcr 6.3.1 CGI.parse on Ruby 4.0

## Dependency

vcr 6.3.1 on Gemfile.lock. Constraint was vcr ~> 6.0. Appraisal locks already had vcr 6.4.0.

## Symptom

bundle exec rspec spec/rubygems_mcp/ on Ruby 4.0.2 fails while loading spec_helper. require vcr raises NameError undefined method parse for class CGI. VCR::Configuration#initialize still called CGI.method(:parse). Ruby 4.0 removed cgi from the default standard library.

## Evidence

Observed on 2026-09-08 with .ruby-version 4.0.2. Stack pointed at vcr-6.3.1/lib/vcr/configuration.rb:505. VCR 6.4.0 was published 2025-12-22 and replaces CGI.parse with URI.decode_www_form (vcr/vcr pull 1059). gemfiles/ruby40.gemfile.lock and gemfiles/ruby34.gemfile.lock already resolved vcr 6.4.0. Root Gemfile.lock had not.

## Suggested fix

Upgrade the root lock to vcr 6.4.0. Raise the gemspec floor to ~> 6.4 so Ruby 4.0 test installs cannot land on 6.3.1.

## Next

None. This lock refresh is the fix. On 2026-09-08, bundle-audit check --no-update on Gemfile.lock, gemfiles/ruby34.gemfile.lock, and gemfiles/ruby40.gemfile.lock each reported No vulnerabilities found. That is an advisory-scanner baseline, not a full dependency audit.
